## 0. 摘要

在绳上最后一张卡右侧留一块**入口区域**。指针进入整条线带（含挂图周围）时，入口先从上到下露出一角；指针移到入口上，一张空白便签迅速落下，停在它**理论上会挂上的槽位**（最后一张卡右侧、与卡片同高），在挂点缓慢上下浮动；指针相对便签中心的距离和方向产生指向指针的拖拽力，与回位弹簧对抗，做出滞后、过冲和惯性。点击它，便签飞到屏幕中央，展开成**无标题栏、无工具栏、无滚动条**的 WYSIWYG 编辑器——只有纸面、玻璃边框和阴影。光标所在行显示 Markdown 原文，其余行实时渲染。点击纸面外或失焦，便签飞回绳上并挂起；挂上即写入 `.txt`；从绳上取下即移入归档。没改内容就点外面时也播同样的飞回动画。

核心约束：

- 源码始终是唯一真相；渲染只是投影。
- 不新增第二套飞行系统，复用现有 `window/flight.rs` 的曲线与交接。
- 不把 continuity 作为依赖；只参考其投影/IME/光标锚定思路，按最小范围改写。
- 不改变截图、图片标注、拖拽、托盘等现有行为。

## 1. 目标与非目标

### 1.1 目标

| # | 目标 |
|:--|:--|
| G1 | 默认不显示完整入口；指针进入工具范围（整条挂线/挂图周围）时，入口从上到下露出一角，指针移到入口才展开完整空白便签 |
| G2 | 入口便签从露角位置迅速落下，停在其理论挂点上下摆动；鼠标距离/角度产生拖拽力，与回位弹簧形成惯性和过冲；点击后飞到屏幕中央 |
| G3 | 编辑器极简：无标题栏、无按钮、无工具栏、无滚动条；纸面 + 玻璃边框 + 阴影 |
| G4 | WYSIWYG：光标所在源码行显示原文，其余行实时渲染 Markdown |
| G5 | 点击纸面外或失焦即提交：便签飞回绳上挂起，写入 `.txt` |
| G6 | 新建便签挂上即存储；已有便签编辑后挂回原卡；从绳上取下即归档 |
| G7 | 动画与现有截图飞行一致：同一曲线、同一弹簧、同一落地交接 |
| G8 | 三语（en/es/zh）、200% DPI、中文 IME 全部可用 |
| G9 | 常驻体积/内存不退化；编辑器只在打开时占资源，关闭即释放 |

### 1.2 非目标（v1 不做）

- 分栏、源码/预览双栏、可拖动分隔条。
- 标题栏、关闭/保存按钮、工具栏、格式按钮、滚动条、状态栏。
- 表格、图片、脚注、HTML、代码块语法高亮、链接跳转、拼写检查。
- 多便签同时编辑、标签页、搜索、导出、归档浏览/恢复界面。
- 移动窗口/手动缩放（窗口固定在屏幕中央；v1.1 再考虑）。
- 富文本复制（复制的是 Markdown 源码）；协作、云同步。
- 每键持久化/崩溃草稿（v1 只在“挂上”时写盘；见 §8.5）。

## 2. 术语与不变量

| 术语 | 含义 |
|:--|:--|
| **工具范围** | 整条线带窗口及其周围约 12 DIP；指针在这里时入口露角 |
| **入口热点** | 最后一张卡右侧的不可见矩形；指针进入即展开完整悬停便签 |
| **悬停便签** | 从露角位置快速落下、停在理论挂点（最后一张卡右侧的下一个槽位）并被鼠标力拖拽的空白便签 |
| **编辑窗口** | 屏幕中央的极简 WYSIWYG 窗口 |
| **活跃行** | 光标所在的**源码行**（以 `\n` 分隔）；v1 只对整行显示原文 |
| **挂上 / hang** | 结束编辑，便签飞回绳上成为卡片，并写入 `.txt` |
| **挂下 / take down** | 从绳上取下，文件移入 `Notes\Archive` |
| **飞行挂起** | 本文定义为：点击纸面外/失焦/Esc 后，结束编辑并飞回绳上挂起；不是“暂停动画” |
| **提交** | 一次从编辑窗口到挂上的完整动作，包含写盘、飞行、落地交接 |

不变量：

1. 便签内容以 `.txt` 源码为准；卡片、飞行纹理、悬停预览都是它的投影。
2. 不新增飞行窗口/动画系统；笔记飞行复用 `window/flight.rs`，只增加“便签 profile”。
3. UI 线程不做写盘、不做大图编解码；提交的写盘走 worker，完成后才落地。
4. 编辑器窗口是唯一一个会抢键盘焦点的便签窗口；悬停便签和飞行窗口都不抢焦点。
5. `.txt` + UTF-8 BOM + CRLF 的既有格式不变；WPF 版仍能打开这些文件。
6. 不引入 `continuity-*` 依赖；不引入 tree-sitter/SQLite/zstd/notify。

## 3. 用户体验流程

### 3.1 入口与悬停

1. 线带已放下，指针在**工具范围内**：整条挂线、绳上的卡片以及线带周围约 12 DIP。
2. 指针一进入工具范围，入口便在上次卡片右侧的槽位**从上到下露出一角**：只画空白便签顶部的 16 DIP（玻璃框 + 纸面顶边），由线带场景以 0.22 s 弹簧滑出；指针离开工具范围即收回。默认仍不显示完整入口。
3. 指针进入最后一张卡右侧的入口热点。热点默认没有任何绘制。
4. 指针进入热点后**立即**（不再等待 120 ms）复用悬停便签窗口，便签从槽位上方 16 DIP 处以 **0.22 s** 落到理论挂点；露出的那一角就是它的起始位置，所以看起来是“剩下部分迅速落下”。
5. 便签在挂点以 **±3 DIP / 0.22 Hz** 上下浮动；鼠标相对便签中心的距离与方向产生指向鼠标的拖拽力，与回位弹簧对抗，形成滞后、过冲、回摆和阻尼。拖拽力有距离上限，不会把便签拉出工作区。
6. 指针离开热点（热点外再留 24 DIP 余量），便签沿 0.42 s 曲线飞回屏幕上方并消失；线带解除临时钉住。便签的物理跟随不能把指针“追”出入口，否则会一直不消失，因此退出判定只看这个固定区域。
7. 指针在便签纸面上时，光标变为手形；点击即进入 §3.2。

完整入口只在热点内出现；工具范围里的露出一角是提前提示，热点内光标变为手形，作为第二重提示。是否保留手形光标见 §13 待确认。

### 3.2 点击进入编辑

1. 点击悬停便签的纸面。
2. 悬停便签隐藏；飞行窗口带着同一张便签，从指针下方飞到屏幕中央的编辑窗口矩形。
3. 飞行使用截图飞行的曲线、弧高、倾角和玻璃边框淡入；到达后编辑窗口在飞行层下方出现，飞行层淡出（落地交接）。
4. 编辑窗口取得键盘焦点，光标在文档开头闪烁。
5. 若便签来自已有卡片（右键“编辑”/长按），则跳过悬停阶段：直接从卡片位置飞到中央，载入原文。

### 3.3 提交与归档

提交（点击纸面外、失焦、Esc、Ctrl+S、WM_CLOSE）：

1. 编辑窗口禁用输入，光标停止闪烁。
2. 若文本为空/全空白：
   - 新建便签：不写文件，纸面缩小、旋转并掉出屏幕（§5.5）。
   - 已有便签：将原文件移入归档，卡片按“挂下”动画落下。
3. 若文本非空：
   - 新建便签：worker 调 `notes::create(text)` 写 `.txt`；成功后创建卡片，便签从编辑窗口飞到新卡片槽位，落地交接；播放 `Tink`。
   - 已有便签：worker 原子写回原路径；成功后卡片原地刷新，便签飞回原槽位，落地交接。
   - 已有便签但文本没变：不写盘，**仍按同样的飞回路径**回到原槽位，避免点外面时窗口凭空消失。
4. 写盘失败：编辑窗口保持打开、输入恢复，玻璃边框闪一次红色，`error.log` 记录；不丢文字。
5. 挂上后更新 `pegged.txt`；线带需要时先 `present`/`reveal`，保证落地时可见。编辑期间线带保持钉住，不会因为指针移到编辑窗口而收起；提交时再按需放下。

挂下（卡片叉、右键“归档”、全部取下、容量淘汰）见 §8.3。

### 3.5 边界情况

| 情况 | 行为 |
|:--|:--|
| 线带为空 | 热点放在空提示右侧 `SPACING` 处；仍可悬停出便签 |
| 线带已满（容量上限） | 新便签挂上时按截图同样的容量策略：最旧卡片落下；若最旧是便签则归档 |
| 线带收起 | 悬停便签/飞行一起取消；编辑窗口不受影响 |
| 编辑期间指针移出线带 | 线带保持放下（编辑器钉住），提交/关闭后才按正常延迟收起 |
| 编辑后挂回 | 线带若被程序性收起，先 `present`/`reveal` 再飞；落点按目标布局计算，不受收起偏移影响 |
| 指针离开热点但停在便签上 | 保持；离开便签纸面后才飞出 |
| 编辑窗口打开时再次悬停入口 | 忽略；不创建第二个便签 |
| 编辑窗口打开时点击线带 | 线带点击被忽略；这次点击只用于提交（见 §5.5） |
| 编辑窗口打开时另一张卡片被外部程序修改 | 编辑窗口持打开时的快照；提交时以编辑内容为准，最后写入者赢，记录 trace |
| 编辑窗口打开时应用退出 | 尝试提交并等待写盘最多 2 s；失败则记录日志后退出（v1 无草稿） |
| 屏幕锁定/UAC/Alt-Tab | 失焦即提交；写盘失败则保持窗口，锁屏回来后仍可继续 |
| 多显示器 | 编辑窗口在入口所在显示器的工作区居中；飞行不跨屏 |
| DPI 改变 | 编辑窗口按新 DPI 重排并重新居中；悬停便签重建 |
| 飞行被新截图打断 | 截图飞行优先；便签飞行立即完成状态（写盘/卡片已就位），不再播放落地 |
| 便签文本只有空白 | 视为空；新建不写文件，已有则归档并取下 |

## 4. 入口热点与悬停便签

### 4.1 位置

以线带的目标布局（不是弹簧当前值）计算，避免卡片滑动时热点跟着漂：

```
last_slot_center = slot_x(count - 1, count, width)        // 有卡片
hotspot.left     = last_slot_center + CARD_WIDTH / 2 + 12
hotspot.width    = SPACING - 12
hotspot.top      = card_top(last_slot_center, width, 0)
hotspot.height   = slot_height(card_height, note)
```

- 空线带：热点以 `width / 2 + SPACING * 0.5` 为中心，尺寸同上。
- 右边界 clamp 到工作区；可用宽度 < 80 DIP 时隐藏热点（仍可用托盘入口）。
- 热点与卡片保持 12 DIP 间隙，不与卡片 10 DIP 悬停宽容区重叠。
- 线带收起时不参与命中。

布局示意（有 3 张卡时）：

```
绳子 ─────────────────────────────────────────────
   [card]   [card]   [card]   [ 空白便签 ]   ← 在理论挂点上下浮动
                                  ↑ 指针力把它拉向鼠标
```


### 4.2 命中、光标与点击穿透

- 指针位置由现有的 30 Hz 全局指针轮询计算，不依赖线带窗口收到 `WM_MOUSEMOVE`。
- 指针在热点内：线带取消点击穿透（`WS_EX_TRANSPARENT` 关闭），光标变手形；离开即恢复。
- 热点内按下鼠标不直接打开编辑器；只有悬停便签出现后点击便签才进入编辑。
- 热点本身不是可点击控件；工具范围里的露角提示由线带场景绘制，鼠标到热点才出现完整便签。手形光标仍是热点内的提示。

### 4.3 悬停时序

| 事件 | 动作 |
|:--|:--|
| 进入工具范围（整条线带 + 12 DIP） | 入口槽位从上到下露出空白便签顶部 16 DIP（0.22 s 场景弹簧）；不创建悬停窗口 |
| 离开工具范围 | 露角收回；完整便签若已出现则走 0.42 s 飞出 |
| 进入热点 | 立即创建/复用悬停便签窗口，从槽位上方 16 DIP 处以 0.22 s 落到理论挂点；同时隐藏露角 |
| 指针在热点∪便签内 | 便签受指向指针的拖拽力 + 回位弹簧 + 上下浮动 |
| 指针离开热点（24 DIP 余量） | 启动 0.42 s 飞出；飞出完成后解除钉住，线带按正常延迟收起；若指针仍在工具范围，下一帧重新露角 |
| 线带被程序性收起 | 立即取消悬停/飞行，并收回露角 |

### 4.4 悬停便签窗口

- 独立顶层窗口：`WS_POPUP | WS_EX_TOOLWINDOW | WS_EX_TOPMOST | WS_EX_NOREDIRECTIONBITMAP`，不抢焦点：`WM_MOUSEACTIVATE → MA_NOACTIVATE`。点击纸面不激活悬停窗口，只把“点击”命令发给 App 进入编辑。
- 内容：**和挂图一致的外框**——144×96 DIP 玻璃卡片（`layout::note_card_size`），136×88 DIP 的空白纸面按 `PHOTO_INSET` 4 DIP 内缩放在里面，圆角、玻璃底、1 px 边框、阴影都与图片卡片相同（`fill_round(Glass)` + `draw_photo(PHOTO_RADIUS)` + `stroke_card(0.75)`）；纸面位图按 3× 渲染一次，窗口 = 卡片 + 四周 24 DIP 阴影 padding（192×144 DIP）。
- 卡片的顶边就是入口槽位的顶边，所以它的外框和绳上卡片的外框同高；卡片中心 = 纸面中心 = 理论挂点。
- 纸面中央用 13 DIP 的灰（`Brush::Placeholder`，`#606060`）画 `i18n::s().new_note`：中文“新建便签”、英文 “New note”、西语 “Nueva nota”。它画在卡片的旋转矩阵里，所以跟着卡片一起倾斜；纸面位图本身仍是空白的，飞行和卡片不会带上这四个字。
- 位置由 `SetWindowPos` 更新（15 ms 定时器）。窗口本身不能旋转，所以**倾斜时重绘窗口内容**：UI 线程把最新角度写进共享槽位并只在没有待处理请求时投递一次 `Turn`，渲染线程读取最新角度、在已就位的窗口里按旋转矩阵重画（外框/纸面/标签/边框/阴影都随卡片转），角度变化小于 0.05° 不重画。请求合并、静止时不重画，所以没有逐帧排队；窗口尺寸不变，因为 5° 倾斜仍在 padding 内。
- 纸面区域可点击；阴影 padding 不接收点击（命中测试返回“外部”，不触发编辑）。命中测试按倾斜角把指针反向旋转回卡片的本地坐标，所以点的是画出来的卡片，而不是未旋转的外接矩形。
- 便签不参与线带卡片布局，不是 `HitCard`，不响应拖拽/叉/色板。
- 空闲 10 s 后销毁窗口与设备（与拖拽 ghost 相同策略）。

### 4.5 飞入、浮动、飞出

飞入/飞出由**悬停窗口本身**沿曲线移动完成（位置 `SetWindowPos`，内容只在倾斜
变化时重绘），不新建飞行窗口；点击后的中央飞行和挂上后的飞回卡片才复用
`window/flight.rs`：

| 参数 | 飞入 | 飞出 |
|:--|:--|:--|
| 时长 | 0.22 s | 0.42 s |
| 曲线 | `ease::in_out_cubic` | 同左（反向） |
| 起点 | 理论挂点上方 16 DIP（露角已经出现） | 当前悬停位 |
| 终点 | 理论挂点（最后一张卡右侧的下一个槽位） | 工作区上方屏幕外 |
| 弧高 | 4 DIP | 22 DIP |
| 倾斜/淡入 | 飞入期间不倾斜（角度 0） | 飞出期间角弹簧回正 |
| 落地交接 | 无（动画结束即悬停） | 无 |

露角由 `scene.rs` 绘制，不创建第二个窗口：在入口槽位画完整空白便签卡片的顶部
16 DIP（`PushAxisAlignedClip` 裁切，玻璃框 + `Brush::NotePaper` 纸面），高度由
0.22 s 弹簧从 0 长到 16 DIP；指针进入热点时立即隐藏，完整便签从同一槽位上方
16 DIP 落下，视觉上就是“剩下部分掉下来”。

悬浮物理（v1 实测参数，`src/app.rs`）：

- 挂点 = 理论槽位的卡片中心；y 上叠加 `sin(2π · 0.22 · t) · 3 DIP` 的上下浮动。
- 回位弹簧：响应 0.56 s、阻尼比 **0.6**（轻微欠阻尼：过冲约 7 % 后回正，不再来回摆）。
- 鼠标力：从便签中心指向鼠标，平衡偏移 = `min(距离 × 0.22, 30 DIP)`，
  260 DIP 外不再施力；它和回位弹簧一起积分（240 Hz 子步），所以便签会滞后、
  轻微过冲，而不是贴着鼠标走，也不会被拉得满条跑。
- 倾斜：以纸面中心为交点的十字线是零度线（两轴上与中心点为 0），左上、右下
  象限顺时针，右上、左下象限逆时针；方向项取 `sin(2φ)`，所以过轴时连续过渡、
  不会跳变。角度 = `5° × sin(2φ) × min(距离 / 120 DIP, 1)`，距离取**便签当前
  中心**到指针的距离：指针靠近中心时几乎不倾斜，对角线方向 120 DIP 外封顶 5°。
- 角弹簧：响应 0.56 s、阻尼比 **0.6**，与平移弹簧同参数，在同一个 240 Hz 子步里
  积分，所以倾斜与拖拽同步滞后、轻微过冲后回正；飞出时目标角变为 0，纸面一边
  上升一边回正。
- 位置 clamp 到工作区（含阴影 padding），不会跑出屏幕；5° 倾斜仍落在窗口 padding
  内，窗口不改变尺寸。
- 指针在热点或便签上时以 15 ms 定时器推进物理；离开两者后飞出。

### 4.6 点击悬停便签

- 左键在纸面按下/抬起 → 进入 `ToCenter`。
- 飞行目标 = 编辑窗口矩形（屏幕物理像素），从当前悬停位飞到目标；使用截图飞行的 0.65 s 曲线、30 DIP 弧高、玻璃边框淡入与落地交接。
- 这次飞行**不画挂夹**：新便签还没挂到绳上，飞行层只淡入玻璃外框和纸面（`Flight::fly` 的 `pin` 参数为 false）。从已有卡片进入编辑器、以及提交后飞回绳上的飞行仍带夹子。
- 飞行期间悬停窗口隐藏；编辑窗口提前创建但隐藏，飞行到达时显示在飞行层下方并淡出飞行层。
- 编辑窗口的纸面矩形必须与飞行层最终纸面矩形逐像素对齐，避免交接跳动。

### 5.1 外观

| 项 | 值 |
|:--|:--|
| 纸面 | **460×360 DIP**（固定；v1 不可缩放） |
| 窗口 | 500×400 DIP，四周 20 DIP 阴影/透明边距 |

| 选区 | 强调蓝 `#0E639C` 30% 透明度 |

| 滚动条 | 无；滚轮/触控板滚动，光标自动进入可视区 |

无标题栏、无按钮、无工具栏、无状态栏、无右键菜单；复制/粘贴/撤销全部走键盘。

### 5.2 窗口属性

- `WS_POPUP`，无 `WS_CAPTION/WS_THICKFRAME/WS_SYSMENU`。
- `WS_EX_TOOLWINDOW`（不进任务栏/Alt-Tab）、`WS_EX_TOPMOST`、`WS_EX_NOREDIRECTIONBITMAP`。
- 使用 DirectComposition + 预乘 alpha 的 composition swap chain；窗口四角与阴影外透明。
- 窗口可取得键盘焦点（与线带不同）；点击纸面即聚焦。
- 不响应拖动/缩放；位置固定在入口所在显示器工作区中央，按 DPI clamp 到工作区内。
- 标题栏图标/任务栏图标都不需要。

### 5.3 渲染

- D3D11 + D2D + DWrite，独立渲染线程；UI 线程只发命令/快照。
- 纸面先渲染到**不透明的离屏位图**（`D2D1_ALPHA_MODE_IGNORE`）：
  - 纸面渐变、折角、文本、光标、选区、IME 组合串都画在位图上，可用 ClearType。
  - 再把位图按圆角裁剪画到预乘 alpha 的窗口目标上，叠加玻璃边框和阴影。
  - 这样既有清晰文字，又有逐像素透明的圆角/阴影；也便于飞行交接复用同一张纸面纹理。
- 离屏位图按纸面物理像素分配（200% 下约 920×720×4 ≈ 2.6 MB），窗口交换链约 6–7 MB；编辑器关闭即释放。
- 光标/选区/组合串只重画脏区；文本/layout 只在 revision 变化时重建。
- 阴影烘焙一次；DPI 改变时重烘。
- 文本抗锯齿在位图上是 ClearType；窗口合成层不需要再做文字抗锯齿。

### 5.5 关闭/提交

提交触发：

1. **点击纸面外**：包括窗口透明阴影边距、窗口外任意位置。
2. **失焦**：`WM_ACTIVATE(WA_INACTIVE)` / `WM_KILLFOCUS`。
3. **Esc / Ctrl+S / WM_CLOSE**。

检测方式：

- 窗口内：`WM_LBUTTONDOWN` 的客户区坐标不在纸面圆角矩形内 → 提交。
- 窗口外：复用现有低层鼠标钩子（`WH_MOUSE_LL`），在鼠标按下时判断点是否在纸面屏幕矩形内；不在则投递提交消息。钩子不吞点击，其他程序仍收到这次点击。
- 失焦：作为钩子的兜底；例如键盘 Alt-Tab、UAC、锁屏。
- 窗口创建/飞行交接期间 `focus_ready=false`；首次 `WM_SETFOCUS` 后置 true；此前的失焦/激活变化一律忽略，避免交接时误提交。
- 所有路径共享一个 `committing` 标志，避免重复提交；提交中打开错误提示时设置 `suppress_commit`，防止 MessageBox 失焦递归提交。
- 编辑窗口打开期间，线带的点击处理直接返回（见 §5.7）；这次点击只用于提交，不会同时触发卡片动作。

**空的新便签（丢弃）**：不写文件，也不让窗口凭空消失——那样看起来像闪退。改为一段
物理动画（`App::discard_new_note` → `Flight::tumble`）：

- 编辑窗口先隐藏，但**等到飞行层的第一帧呈现**（`FlightEvent::Started`）才隐藏，
  纸面在两扇窗之间不会闪空。
- 纸面位图用 `notes::render_paper(460, 360, color)` 按编辑纸面尺寸重新渲染（2×），
  不拉伸卡片位图，折角仍是 13 DIP。
- 起点 = 编辑纸面矩形，飞行卡片比纸面四周各多 4 DIP（`PHOTO_INSET`），交接时
  纸面大小不变、只多出一圈玻璃外框。
- 前 0.3 s 缩到 **45 %**（ease-out），同时获得随机方向的自转（**140–260 °/s**，
  左右随机）和随机方向的初速度（横向 ±60–180 DIP/s、向上 60–200 DIP/s）；
  之后只受重力 **2600 DIP/s²**，按真实帧 `dt` 积分，直到整张纸落到窗口底边
  （桌面底边）以下。实测一次 0.89 s、56 帧、转角 202°。
- 飞行窗口按整条下落路径取包围盒（约 1800×2200 物理像素），结束后随空闲策略释放。
- 期间 `note_tumbling` 为真：点击不再重复提交；2.5 s 兜底期限保证即使飞行被截图
  打断，隐藏的编辑窗口也会被释放。

### 5.6 错误状态

- 写盘失败：窗口不关闭，输入恢复；玻璃边框闪一次 `#C42B1C` 红色（120 ms），`error.log` 记录；不弹 MessageBox（会再次失焦）。
- 归档失败：卡片保留，托盘气泡提示“无法归档”，`error.log` 记录。
- 重复提交/并发：`committing` 标志；第二次触发直接忽略。

### 5.7 焦点、层级与线带

- 编辑窗口 `WS_EX_TOPMOST`，显示后位于线带之上；线带仍在顶部，但不会盖住中央的编辑窗口。
- 编辑窗口打开时线带临时钉住，保持可见，便于落地交接；提交完成后解除。
- 编辑窗口打开期间，`App` 忽略线带的卡片点击/右键/悬停动作，避免“编辑中把卡片归档”的竞态。
- 编辑窗口关闭/提交完成后恢复正常线带交互。

### 5.8 DPI 与多显示器

- 在入口所在显示器的工作区居中；窗口尺寸 DIP 固定，物理像素按 DPI 换算。
- 工作区放不下 500×400 DIP 时，按 90% 等比缩小纸面（低于 360×280 DIP 时改为铺满工作区并允许内部滚动）。
- `WM_DPICHANGED`：重建 D2D/DWrite 资源、重烘阴影、重排文本、重新居中。
- 不跨显示器飞行；如果在编辑期间显示器配置变化，按新工作区重新定位。

## 6. WYSIWYG 行为

### 6.1 核心规则

1. 源码始终保存为 Markdown 文本（`.txt`）。
2. **活跃行**（v1 = 光标所在源码行）显示原文；其他源码行渲染。粒度选择见 §6.1.1。
3. 活跃行保留所在块的样式：
   - 标题行：标题字号/字重；`#` 标记用 45% 墨色。
   - 列表行：正文样式；`- ` / `1. ` 标记用 45% 墨色，不额外画项目符号。
   - 引用行：引用墨色；`> ` 标记淡化。
   - 代码块行：等宽字体；三个反引号标记淡化。
   - 普通段落：正文样式；行内标记（`**`、`` ` `` 等）淡化。
4. 活跃行**不应用**行内强调/链接/代码样式；整行按块的基础样式绘制，只淡化 Markdown 标记。这样不会出现“半截粗体/半截原文”的割裂。
5. 光标离开该行后，该行立即重新渲染为 WYSIWYG。
6. 便签 Markdown 是**行导向**的：单个换行就是换行，不做 CommonMark 的“软换行合并为空格”。空行分段。
7. 解析失败/不支持的语法：该块降级为原始文本显示，不丢字符、不吞行。

#### 6.1.1 活跃行粒度

“活跃行”不是 Markdown 的概念，而是显示层选择：光标附近多大范围显示原文。三种粒度：

| 粒度 | 显示原文的范围 | 重排范围 | 标记完整性 | 实现难度 |
|:--|:--|:--|:--|:--|
| 视觉行 | 光标所在换行后的视觉行 | 最小 | 可能只看到半个标记 | 高（需要稳定源区间，避免振荡） |
| 源码行（v1） | 光标所在 `\n` 行 | 一行（可能折成多行） | 完整（该行内） | 中 |
| 块 | 整个段落/列表项/块引用/代码块 | 最大 | 最完整 | 中低 |

为什么 v1 选源码行：

- 便签是行导向的；多数源码行在 460 DIP 纸面（约 400 DIP 文本宽）内只占一个视觉行（约 50 个拉丁字符 / 26 个 CJK 字符），三种粒度没有区别。
- 源码行是连续的源码区间，显示映射、点击、选区、撤销都简单；揭示范围固定，不会因为重排而改变。
- 视觉行级看似更细，但“行”由渲染后的换行决定；揭示原文会改变宽度/换行，从而改变“哪一行是活跃行”，容易振荡。要稳定，必须先把揭示范围固定成一个源码区间（通常是揭示前那一行的源码范围），再允许它折成多行；实现上已经不是“单行”，而是“源区间”。这是 +3–5 人日的主要来源。
- 视觉行级的另一个问题是半个构造：如果 `**bold**` 横跨两行，光标在第二行时只显示结尾的 `**`，看不到开头的 `**`；光标在第一行时只看到开头，看不到结尾。源码行级至少保证同一 `\n` 行内的标记完整。

什么时候值得升级：

- 用户经常写很长的单行段落（不按回车），或很长列表项/代码行，在 460 DIP 宽度下折成 3 行以上。
- 视觉测试显示光标进入长行时整段跳动超过 2–3 行，打断阅读。
- 升级时保留 `Line`/`Row` 两级映射（v1 就把行内折行信息存下来），避免重写解析器。


### 6.2 Markdown 子集（v1）

| 语法 | 渲染 | 活跃行 |
|:--|:--|:--|
| `#`–`######` 标题 | 字号/字重分级；1–3 级明显，4–6 级递减 | 显示 `#` 标记 + 标题样式 |
| `**bold**` / `__bold__` | 粗体 | 显示标记，正文不加粗 |
| `*italic*` / `_italic_` | 斜体 | 显示标记 |
| `~~strike~~` | 删除线 | 显示标记 |
| `` `code` `` | 等宽 + 浅色底 | 显示反引号 |
| 围栏代码块（三个反引号） | 等宽 + 浅色底 + 左侧细线；不做语法高亮 | 围栏行显示三个反引号 |
| `-` / `*` / `+` 列表 | 圆点 + 缩进 | 显示 `- ` 标记 |
| `1.` 有序列表 | 数字 + 缩进 | 显示 `1. ` 标记 |
| `- [ ]` / `- [x]` | 复选框图形；点击可切换（v1.1 可选） | 显示 `- [ ]` 原文 |
| `>` 引用 | 左侧 2 DIP 竖线 + 缩进 + 引用墨色 | 显示 `> ` |
| `[text](url)` | text 带下划线/强调色；不跳转 | 显示完整源码 |
| `---` / `***` / `___` | 1 DIP 分隔线 | 显示原文 |
| 空行 | 空行，保持行高 | 光标可见 |
| 表格 | v1 按原始文本块显示 | 原文 |
| 图片 `![alt](url)` | 只显示 alt 文本 | 原文 |
| HTML/脚注 | 原始文本 | 原文 |

### 6.3 显示映射

解析使用 `pulldown-cmark` 的 **offset iterator**（`into_offset_iter`），每个事件带源码字节范围。构建：

```
Block { kind, source_range, lines: Vec<Line> }
Line  { source_range, runs: Vec<Run>, height, indent, marker }
Run   { text, source_range, style, visible }
```

- `visible=false` 的 run 是 Markdown 标记（`#`、`**`、`` ` ``、`- `、`>`、链接括号等），渲染时宽度 0。
- 每个源码行一条 `Line`；行内 run 按源码顺序排列，标记 run 隐藏。
- `source_to_line` / `line_to_source` 用于光标、点击、选区。
- 点击：先由 `HitTestPoint` 找到行，再在该行可见 run 中找最近的源码边界；落在隐藏标记上时吸附到标记前/后（按点击方向）。
- 光标移动：源码字节偏移；向上/下移动时按目标行的 x 找最近边界；跨行时保留列偏好。
- 选区：源码范围；渲染行只高亮可见 run；活跃行高亮整段原文。复制仍取源码子串（含隐藏标记）。
- 行高变化：光标行从渲染变为原文时，行高可能变化；以光标所在行为锚点，调整滚动偏移，保持光标视觉位置稳定。

### 6.4 编辑操作

- 插入/删除都直接改 `String`，保持字节索引；光标/选区是字节偏移，必须落在 UTF-8 字符边界。
- 撤销：快照式（`text + caret + selection`），连续输入 500 ms 内合并；最多 100 步；笔记体积小，内存可接受。
- 输入法组合串：见 §6.6。
- 链接/复选框不响应鼠标点击（v1）；点击它们等同点击文本。
- 列表自动续行、复选框点击切换、代码块缩进辅助：v1.1 可选，不阻塞 v1。

### 6.5 渲染细节

| 元素 | 规则 |
|:--|:--|
| 标题 1–6 | 24 / 21 / 18 / 16 / 15 / 15 DIP，粗体；上下留白 10/6 DIP |
| 段落 | 15 DIP，行高 1.55；段间距 6 DIP |
| 粗体/斜体 | DWrite `SetFontWeight` / `SetFontStyle` 按 run 设置 |
| 行内代码 | Consolas 13.5 DIP；背景 ink 4%；圆角 3 DIP；左右 3 DIP padding |
| 代码块 | Consolas 13.5 DIP；背景 ink 4%；左侧 2 DIP 竖线；块内行距 1.4 |
| 列表 | 缩进 18 DIP/级；圆点 4 DIP；有序列表数字右对齐 |
| 引用 | 左侧 2 DIP 竖线（ink 25%）；内容缩进 12 DIP；ink 80% |
| 链接 | 下划线；强调蓝 `#0E639C`（纸色上可读） |
| 分隔线 | 1 DIP，ink 20%，上下 8 DIP |
| 复选框 | 12 DIP 方框，1.2 DIP 边；勾选时画勾 |
| 折角 | 右下 18 DIP，画在文本下层；文本内边距避开 |

所有度量按 DIP，DWrite 用 DPI 缩放；文本布局宽度 = 纸面宽 - 左右内边距。

### 6.6 IME

- `WM_IME_STARTCOMPOSITION` / `WM_IME_COMPOSITION` / `WM_IME_ENDCOMPOSITION`。
- `GCS_RESULTSTR`：取 `ImmGetCompositionStringW`，插入到光标处，清组合串。
- `GCS_COMPSTR`：取组合串；在光标处插入一个临时组合 run，活跃行按“源码 + 组合串”重排；组合串带下划线；不写入源码，直到 RESULT。
- 组合串只在活跃行内绘制；不把整篇文档切回原文。
- 候选窗：沿用标注编辑器的 `ImmSetCompositionWindow(CFS_POINT)` + `ImmSetCandidateWindow`，坐标用光标的客户区物理像素；200% DPI 实测。
- 组合期间不重新解析 Markdown（避免把拼音当 Markdown 标记）；只重排活跃行。
- 组合串为空时删除临时 run。
- 输入法提交的中文/日文/表情按 UTF-16 代理对处理；插入前转 UTF-8 字符边界。

### 6.7 性能

- 每次编辑：重新解析整篇（pulldown-cmark，笔记通常 < 10 KB）+ 重建显示映射 + 只重排脏行。
- 目标：按键到像素 p95 ≤ 16 ms（100% DPI）、≤ 20 ms（200% DPI）；10 KB 笔记首次解析 ≤ 3 ms。
- 渲染线程缓存 DWrite layout；光标/选区/闪烁只重画脏区，不重建 layout。
- 如果实测超预算：先做行级增量解析/缓存，再考虑后台解析；v1 不做复杂增量。
- 无每帧堆分配：布局缓存、scratch buffer 复用；编辑器不是 60 fps 线带，但仍遵守项目规则。

### 6.8 兼容性

- 文件仍是 `.txt` + BOM + CRLF；WPF 版能打开，只是按纯文本显示 Markdown 标记。
- 旧便签按 Markdown 解释；以 `#`/`-`/`>`/`1.` 开头的旧文本会变成标题/列表/引用。这是已知行为变化，见 §13 待确认。
- 卡片摘要用 `notes::summary(text)` 去掉常见标记，保持卡片干净；旧纯文本基本不变。
- 复制便签仍是 Markdown 源码；粘贴到其他应用得到源码。

## 7. 飞行与交接

### 7.1 复用现有飞行

不新建飞行窗口。复用 `src/window/flight.rs`：

- 时长 0.65 s；`ease::in_out_cubic`。
- 尺寸在起点/终点矩形之间线性插值。
- 中心沿正弦弧抬高 30 DIP。
- 倾角按进度施加；玻璃边框在 0.10–0.55 淡入。
- 落地后飞行层在 0.16 s 内淡出，真实卡片/窗口在下方。
- `Present(1, 0)` 跟随显示器刷新率；不硬编码 16.6 ms。

新增一个**便签 profile**：

- `FlightCommand::Fly` 增加 `kind: Card | Note`（或 `note: bool`）。
- 便签 profile 不画照片内框；画纸面纹理 + 玻璃边框 + 阴影；夹子只在“飞回绳上”的最后 25% 淡入。
- 便签纹理由编辑窗口/悬停窗口按目标物理尺寸渲染；飞行层只负责缩放/位移/倾角。
- 从编辑窗口飞到绳上时，夹子/卡片边框在最后 25% 淡入；从悬停飞到中央时，夹子不出现。
- 飞行窗口仍是池化的；不新增 D3D 设备/交换链。

### 7.2 四段飞行

| 飞行 | 起点 | 终点 | 时长 | 弧高 | 交接 |
|:--|:--|:--|--:|--:|:--|
| 悬停飞入 | 理论挂点上方 16 DIP（露角已出现） | 理论挂点（下一卡片槽位中心） | 0.22 s | 4 DIP | 无，动画结束显示悬停窗口 |
| 悬停飞出 | 当前悬停位 | 工作区上方屏幕外 | 0.42 s | 22 DIP | 无 |
| 飞到中央 | 悬停便签矩形 | 编辑窗口矩形 | 0.65 s | 30 DIP | 编辑窗口在下方，飞行层淡出 0.16 s |
| 飞回绳上 | 编辑窗口矩形 | 目标卡片槽位矩形 | 0.65 s | 30 DIP | 卡片在下方，飞行层淡出 0.16 s |

- 起点/终点都是屏幕物理像素矩形；飞行窗口的 origin 取两者并集 + 60 DIP + 5% padding。
- 起点可以在屏幕外（负坐标）；飞行窗口允许部分在屏幕外，落地前完全进入工作区。
- 便签纹理按起点/终点中较大的物理尺寸渲染，避免放大模糊；编辑窗口往返用编辑尺寸，悬停阶段用 3× 卡片尺寸。
- 飞行期间线带先 `present`/`reveal`；如果线带原来收起，先放下再起飞/落地。

### 7.3 交接

**中央交接（悬停 → 编辑）**

1. 飞行到达编辑窗口矩形；编辑窗口已创建并绘制好纸面，但隐藏。
2. 显示编辑窗口，飞行层在其上方继续画同一张便签；0.16 s 内飞行层 alpha 1→0。
3. 两者纸面矩形逐像素对齐；玻璃边框/阴影一致；不允许出现一帧空白或双重阴影。
4. 交接完成后飞行层隐藏，编辑窗口取得焦点。

**绳上交接（编辑 → 卡片）**

1. 写盘成功；卡片以 `flying`/`arriving` 状态加入场景（与截图落地相同）。
2. 飞行从编辑窗口矩形飞到卡片槽位；到达时卡片已不透明在下方。
3. 飞行层 0.16 s 淡出；卡片行弹簧按现有逻辑滑动/摆动。
4. 夹子/卡片边框在飞行最后 25% 淡入，避免中央无夹子、绳上有夹子的突变。

### 7.4 打断与优先级

- 截图飞行优先。便签飞行进行中被新截图打断时：
  - 写盘/归档已经完成，卡片/文件状态正确；
  - 飞行立即结束，卡片直接显示（无落地动画）；
  - `error.log` 记 trace，不重试动画。
- 连续悬停/离开：用 generation token 取消旧飞行；不排队。
- 编辑窗口打开期间不触发新的悬停飞行。

### 7.5 性能与内存

- 悬停便签纹理 408×264（3×），约 0.4 MB。
- 编辑窗口纸面纹理按物理像素（200% 约 2.6 MB）；飞行层上传的副本在飞行结束释放，编辑窗口自己的位图保留到关闭。
- 飞行窗口复用现有池化设备；不新增常驻内存。
- 编辑窗口关闭后释放 D3D/D2D/位图；常驻内存回到基线。

## 8. 存储与归档

### 8.1 文件格式

- 路径：`%LOCALAPPDATA%\Pegline\Notes\便签 yyyy-MM-dd HHmmss.txt`（沿用 `notes::create`）。
- 编码：UTF-8 带 BOM；换行 CRLF；读取时容忍 BOM 和 LF/CRLF。
- 原子写：同目录临时文件 + `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`；失败保留原文件。
- v1 **只在挂上时写盘**，不做每键持久化；崩溃/断电会丢失未挂上的编辑内容（见 §8.5）。
- 文件名冲突：沿用 `unique_path` 追加序号。

### 8.2 挂上

| 来源 | 行为 |
|:--|:--|
| 新建、非空 | worker 写新文件；创建卡片；飞到末尾槽位；更新 `pegged.txt`；`Tink` |
| 新建、空 | 不写文件；便签飞回入口方向消失；无卡片 |
| 已有、有变化 | 原子写回原路径；卡片原地刷新；飞回原槽位；不新建卡片 |
| 已有、无变化 | 不写盘；按同样的飞回飞行回到原槽位，然后关闭窗口；卡片保持 |
| 已有、被清空 | 原文件移入归档；卡片按挂下动画落下 |

- 写盘在 worker；UI 线程等待 `Saved`/`Failed` 事件，期间窗口禁用输入。
- 写盘成功后更新 `item.last_write`，避免 1 s 磁盘轮询重复解码。
- 卡片缩略图由 `notes::render(text, color)` 在 worker 重绘；新卡片走现有 `on_note_ready` 流程。
- 颜色沿用卡片当前颜色；编辑器内不提供换色。

### 8.3 挂下与归档

- 归档目录：`%LOCALAPPDATA%\Pegline\Notes\Archive`。
- `notes::archive(path)`：创建目录；`MoveFileExW` 到 `Archive\<原名>`；重名追加 ` (2)`；失败返回错误。
- 触发：
  - 便签卡片叉。
  - 右键菜单“归档”（便签专用；替换原“丢弃”）。
  - “全部取下”：便签归档，图片按原行为。
  - 容量淘汰：便签落下时归档，不静默删除。
  - “保存到桌面”：复制后取下卡片，原文件仍在 Notes（不归档）；行为不变。
  - 拖到资源管理器：由外壳移动/复制，不额外归档。
- 归档成功后从 `pegged.txt` 移除；颜色设置保留（无害）。
- 归档失败：卡片保留，托盘气泡提示，`error.log` 记录。
- 归档是移动，不经过回收站；`Archive` 目录可由资源管理器打开。
- v1 不提供应用内恢复；v1.1 可加托盘“打开便签归档”。

### 8.4 启动与恢复

- 启动只恢复 `pegged.txt` 里的便签；归档不自动恢复。
- 同一段文字再次 `Ctrl+Alt+N`：只在**活动** Notes 目录（不含 Archive）查找；归档的便签不会自动挂回。
- 便签颜色仍按文件名存 `noteColor:<文件名>`；归档后可保留。
- 旧 `.txt` 便签直接按 Markdown 打开；不做迁移/重命名。

### 8.5 并发、外部编辑与崩溃

- 编辑器打开时记录文件 mtime；提交时如果 mtime 变了，仍然以编辑器内容为准（最后写入者赢），trace 记录一次。
- 外部程序（Notepad）正在写同一文件时，原子写可能失败；失败保持窗口，提示重试。
- v1 不做崩溃草稿；如果用户强杀进程，未挂上的内容丢失。v1.1 可加“每 2 s 写 `%TEMP%` 草稿，下次启动询问恢复”。
- 应用正常退出时尝试提交打开的便签，最多等 2 s；失败记录日志。

## 9. 与 continuity 的关系

### 9.1 原则

- **参考，不依赖**：不添加 `continuity-*` 依赖，不引入 `continuity-ui`、`continuity-persist`、`tree-sitter`、SQLite、zstd、notify、`windows 0.59`。
- **最小裁剪**：只取“源码 ↔ 显示映射、活跃行原文、IME 组合、光标锚定”四类思路；不取应用外壳、主题、标签页、分栏、搜索、持久化。
- **改写纳入**：按 Pegline 的 `Surface`/D2D/DWrite/`notes` 类型重写；不直接粘贴大段代码。
- **许可证**：continuity 是 MIT。若复制/实质改编了代码，文件头注明来源，并在 `THIRD-PARTY-NOTICES.md` 附 MIT 全文与版权声明。

### 9.2 取什么 / 不取什么

| continuity 位置 | 取什么 | 怎么改 |
|:--|:--|:--|
| `crates/display_map`（约 25 个文件） | 源码↔显示行的映射、行索引、光标锚定概念 | 只做 `Block/Line/Run` + 字节范围 + 行索引；不移植 fold/table/image/wrap cache |
| `crates/ui/src/window_markdown_inline.rs` | 活跃行显示原文、其余行渲染的 inline reveal 规则 | 简化为源码行级；标记淡化 |
| `crates/ui/src/window_ime.rs` | `WM_IME_COMPOSITION` 流程、候选窗定位、行内组合串 | 适配 Pegline 的 Surface/命令队列；组合串只重排活跃行 |

| `crates/render` 的 Markdown 样式 | 标题层级、列表/引用/代码的视觉比例 | 只作参考；用 Pegline 的 D2D 画 |
| `crates/decorate`（tree-sitter） | 不取 | 改用 `pulldown-cmark`；不引入 tree-sitter |

### 9.3 为什么不是依赖

- `continuity-ui::EditorControl` 是**工作区源码、未发布**，依赖整棵应用 UI 树；git/vendor 会编译数百个文件。
- 依赖闭包含 `rusqlite`（bundled SQLite）、`zstd`、`tree-sitter-md`、`notify` 等；Pegline 只需要 `windows`。
- `windows 0.59` 与 Pegline 的 `windows 0.62` 同时链接，增加体积/编译时间。
- `EditorControl` 是 `WS_CHILD` + `WM_PAINT`，需要普通父窗口，主题/交互与 Pegline 不一致。
- 上游仍在快速变化；vendor 一个 fork 是长期维护项目。

如果未来要验证，只做 1–2 天 spike 量体积/内存/构建时间；预期结论仍是“不依赖”。

## 13. 待确认

> 2026-11-04 实现时按本文的默认选项处理；以下问题保留，若改变需要同步
> `docs/BEHAVIOR.md` §10.1 与 `docs/DECISIONS.md` D9。

1. **“飞行挂起”的语义**：本文按“点击纸面外/失焦 → 结束编辑 → 飞到绳上挂起（保存）”理解。如果你的原意是“暂停飞行/取消”，需要改。
2. **Esc 行为**：本文按“提交（挂上）”处理；是否改成“取消并丢弃本次编辑”？
3. **空文本**：新建空便签不写文件；已有便签被清空则归档并取下。是否符合预期？
4. **入口提示**：热点内是否显示手形光标？本文建议显示；如果要求完全无提示，可去掉。
5. **活跃行粒度**：v1 按“源码行”整行显示原文；是否接受？continuity 的 README 只说 “caret line”，没有明确是源码行还是视觉行；其 display map 的复杂度主要来自 fold/table/wrap，不能直接推断它只揭示一个视觉行。
6. **归档位置**：`Notes\Archive` 是否合适？是否需要托盘“打开便签归档”/应用内恢复？
7. **归档触发**：叉、右键“归档”、全部取下、容量淘汰都归档；是否包括“保存到桌面”后的原文件？
8. **窗口尺寸**：460×360 DIP 纸面是否合适？是否需要可拖动/可缩放？
9. **便签颜色**：编辑器内不提供换色；是否需要在编辑器里也能换？
10. **草稿**：v1 不做每键持久化/崩溃草稿；是否接受“挂上才存储”？
11. **点击穿透**：点击纸面外的那次点击，是否也要传递给下面的应用？本文按“只提交，不额外传递”处理（窗口外点击仍会到达目标应用；窗口透明边距内的点击不会）。
12. **手形光标/热点点击穿透**：热点内关闭线带点击穿透会暂时挡住下方应用；是否接受？

## 14. 决策记录（确认后写入 DECISIONS）

| # | 决策 | 理由 |
|:--|:--|:--|
| N1 | 便签编辑器用 WYSIWYG，不分栏 | 用户选择；便签是写作面，不是代码编辑器 |

| N4 | 挂上即存储，挂下即归档 | 无保存按钮；取下不丢数据 |
| N5 | 继续 `.txt` + BOM | 保持 D5/WPF 兼容；Markdown 只是内容 |
| N6 | 参考 continuity，不依赖 | 避免 SQLite/tree-sitter/整树依赖与维护风险 |
| N7 | 复用现有飞行系统 | 动画一致；不新增设备/窗口 |
