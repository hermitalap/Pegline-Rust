# AGENTS.md

Working notes for anyone (human or agent) changing this repository.

## What this is

Pegline is a Windows port of [Tendedero](https://github.com/alejandrobujan/tendedero): screenshots
hang on a clothesline along the top of the screen. C# / WPF, **zero dependencies**.

## Build, test, run

```powershell
build.cmd            # -> build\Pegline.exe  (single file, ~150 KB)
test.ps1             # builds and runs tests\PreviewTests.exe, must print "All preview tests passed."
```

Rules that are easy to get wrong:

- **Never use `dotnet build`, MSBuild or Visual Studio.** There is no `.csproj` and none is wanted.
  `build.ps1` calls the C# compiler that ships with Windows
  (`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`) against the WPF reference assemblies
  in that same folder.
- **The compiler is C# 5.** No string interpolation (`$"..."`), no `?.`, no `nameof`, no
  expression-bodied members, no `out var`, no tuples. Use `string.Format`.
- The icon is generated by `tools\MakeIcon.cs` during the build and passed as `/win32icon:`.
  Compiling `src\*.cs` by hand without that flag produces an exe with no icon — always use `build.ps1`
  when the result is meant to be run.
- The app is a tray app. After a rebuild, the running copy keeps the old code until it is quit
  (tray → 退出 Pegline) and started again.

## Layout

| Path | What |
|:--|:--|
| `src/*.cs` | one class per file, no partials; `App.cs` is the controller (tray, hotkeys, reveal rules) |
| `src/app.manifest` | Per-Monitor V2 DPI awareness — do not weaken it |
| `tests/` | `PreviewTests.cs` + `HoverPreviewTests.cs`, compiled together with `src` |
| `tools/MakeIcon.cs` | draws the icon at build time |
| `build/` | generated, git-ignored: exe, icon, and the local measurement tool |

## Conventions

- **Units.** Outside a window everything is *device pixels* (pointer, screens, capture areas, card
  frames). Inside a window everything is *WPF units*, and each window scales by the DPI of the
  screen it sits on (`ScreenWindow.Place`, `Scale`, `DipWidth`). Mixing the two is the usual bug.
- **Windows** are borderless, `AllowsTransparency = true`, `Topmost`, and never take focus
  (`WS_EX_NOACTIVATE`). They receive the mouse only over photos (`WS_EX_TRANSPARENT` toggling).
- **Animation** is hand-integrated springs (`Spring` in `Support.cs`), stepped from
  `CompositionTarget.Rendering`. No Storyboards, no WPF animations: the feel matches the macOS
  original's `spring(response:dampingFraction:)`.
- Comments and identifiers are English; user-facing strings go through `Loc.L(en, es, zh)`.
- Settings are plain `key=value` in `%APPDATA%\Pegline\settings.ini` via `Settings`.

## Performance rules learned the hard way

A transparent (`AllowsTransparency=true`) WPF window is composited on the **CPU**. Measured on a
6K screen (6016×3384 @200%):

- Cost scales with the **animated area**, not with the window size: a full-screen transparent
  window with a small moving card still runs at 60 fps; the same window redrawing a 5 MP photo
  drops to ~9 fps.
- `DropShadowEffect` is **re-blurred on every frame** while the element it is attached to is being
  resized or transformed. On a card at take-off size this alone halved the frame rate.
- Per-frame layout (`Margin`, `Clip`, `Width/Height`, `Canvas.SetLeft`) and per-frame object
  allocation (new `RectangleGeometry`, new `Transform`) both show up in the frame budget; reuse
  frozen objects and prefer transforms over layout.
- Never decode, encode or pixel-compare a screenshot on the UI thread. A 6K PNG is ~200 ms to
  encode, ~150 ms to decode, and comparing two of them ~400 ms. Use a worker and come back to the
  UI thread (`Background.Run` in the optimisation branch).

## Measuring

`build\probe\Probe.exe` (git-ignored, compiled from `build\probe\Probe.cs` + `src\*.cs`) is the
local frame-rate tool. Rebuild it with:

```powershell
csc /target:exe /main:Pegline.Probe /out:build\probe\Probe.exe <wpf refs> src\*.cs build\probe\Probe.cs
```

Modes: `mode=flight` (the real `Flight` animation, `spanw/spanh` = capture size, `repeat=2` = cold
then reused window), `mode=bench` (synthetic window, `layered/shadow/anim/img/scaling/cache`),
`mode=decode` / `mode=encode` (real PNG cost), `mode=line` (real line window with real cards),
`mode=dpi`. Every run prints `RESULT ... fps p50 p95 max jank cpu_ms_frame`.

## Workflow for changes

1. Change **one thing**. Keep the diff readable.
2. `build.cmd`, then `test.ps1`.
3. Restart the app (quit from the tray, start `build\Pegline.exe`).
4. Check the behaviour by hand — the animations are the product.
5. Update `PLAN.md` (status + measurement) before starting the next item.

## Git

- `build/` is ignored; never commit generated files.
- Source files use CRLF and UTF-8 **without** BOM. Keep it that way (a file written with LF shows
  up as a whole-file diff).
- Commit messages: short imperative subject, `fix:` / `feat:` / `perf:` prefix, Chinese or English
  both used in history.
